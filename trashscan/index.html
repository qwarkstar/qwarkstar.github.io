TrashScan

Smart metal detection for restaurant waste.

A prototype smart trash can that detects metal utensils in restaurant waste, retrieves them with a motorized pulley mechanism, and sanitizes them under UV light. Built with Arduino, custom electronics, and a 3D printed enclosure.

Sec. 01 / The problem

Thousands of forks. Thrown out every day.

Restaurants discard reusable metal utensils with food waste every shift, losing real money to replacement costs and inventory turnover. Every fork that ends up in landfill is also raw material, manufacturing, and transport energy that can't be recovered. And buried inside black trash bags, those same utensils cut the workers who handle them downstream.

TrashScan catches metal at the source, before it leaves the bin.

Sec. 02 / The solution

Detect. Retrieve. Sanitize.

TrashScan watches the waste stream using an induction loop, lifts recovered metal out with a motorized pulley, and disinfects it under UV light before it is returned to circulation.

01
Spec / Input

Sense

A copper induction loop made from 0.9 mm enameled wire generates an alternating magnetic field. Metal entering the field induces eddy currents, shifting the voltage decay that the Arduino reads.

02
Spec / Logic

Confirm

Firmware requires 5 consecutive positive readings spaced 500 ms apart before acting. This multi-read window kills the false positives that plagued early tests.

03
Spec / Drive

Retrieve

A stepper motor pulls a magnet through a block-and-tackle pulley setup. The pulley halves the force required, letting a small motor reliably lift the recovered item.

04
Spec / Output

Sanitize

Once the magnet returns with its load, UV lights switch on to disinfect both the hook and the recovered item before the cycle resets.

Sec. 04 / Firmware logic

Five reads before I believe you.

Early testing showed that a single positive reading from the induction loop was not trustworthy. Ambient noise, transient electrical fluctuations, and nearby metal all caused false positives.

To reject that noise, the Arduino firmware runs a simple counter algorithm: it takes a fresh reading every 500 ms, and only confirms metal presence after five consecutive positive reads. Miss one, and the counter resets to zero.

After detection, the system hands control to a small state machine that fires the stepper motor, runs the retrieval cycle, activates UV, then enters an override hold state until the operator presses the button to continue.

Src / Arduino C trashscan.ino 
// Confirm metal only after 5 valid reads
const int READS_NEEDED = 5;
const int INTERVAL_MS  = 500;

int positiveCount = 0;
bool retrieving   = false;

void loop() {
  if (retrieving) {
    if (digitalRead(RESET_BTN) == HIGH) {
      retrieving = false;
      positiveCount = 0;
    }
    return;
  }

  if (metalDetected()) {
    positiveCount++;
    if (positiveCount >= READS_NEEDED) {
      runRetrievalCycle();
      activateUV();
      retrieving = true;
    }
  } else {
    positiveCount = 0;
  }

  delay(INTERVAL_MS);
}

Sec. 06 / Iteration

What went wrong, and what we did about it.

Every failure mode from early testing, paired with the fix that shipped in the final prototype.

01
Problem

Induction loop threw false readings from ambient noise and nearby metal during testing.

Fix

Added a counter that requires 5 positive reads spaced 500 ms apart before acting.

02
Problem

Early 0.5 mm wire version produced no sensor output at all.

Fix

Isolated a wiring issue, rebuilt the loop with 0.9 mm enameled copper wire that gave reliable readings.

03
Problem

The stepper motor did not have enough torque to lift items directly.

Fix

Switched to a block-and-tackle pulley setup, which halved the lifting force required.

04
Problem

Sensor kept re-detecting metal that was already retrieved, triggering endless cycles.

Fix

Added a manual button override so detection only resumes after the operator confirms retrieval.
